# SNS投稿の完全取得

## なぜこれが要るか

WebFetch はこの2サイトに対して機能しない。HTMLをテキスト化して小さいモデルに要約させる仕組みのため、
次の3つの理由で中身に到達できず、**取得できなかった部分が推測で埋められた出力が返る**。

1. X は未認証アクセスに HTTP 402 を返す（本文ゼロ）
2. Instagram はログイン壁を返す（OGPの断片のみ）
3. 両サイトとも、情報の多くが**画像の中**にある（表、スクリーンショット、カルーセル）。
   テキスト変換では画像内の文字は一切読めない

過去に、この経路で存在しないリポジトリ名を実在するものとして報告した事故がある。
**推測が混ざった要約は、正しく見えるので気づけない。必ずこのスキルを通すこと。**

## 使い方

`fetch_post.py` はこの SKILL.md と同じディレクトリにある。ユーザー用なら
`~/.claude/skills/sns-fetch/`、リポジトリ同梱なら `<repo>/.claude/skills/sns-fetch/`。

```bash
python3 <このSKILL.mdのあるディレクトリ>/fetch_post.py "<URL>" <出力先ディレクトリ>
```

出力先は作業用の一時ディレクトリにする（リポジトリを汚さない）。
出力先に `content.md`（本文、画像は `[IMAGE n: パス]` で位置を示す）と `img_NN.jpg`（全画像）が出る。
追加インストールは不要。Python標準ライブラリと `curl` だけで動く。

## 手順

1. 上のコマンドを実行する
2. `content.md` を Read する
3. **`[IMAGE n: ...]` のパスを Read ツールで全部開く。** ここを飛ばすと画像内の情報を落とす。
   枚数が多い場合でも、少なくとも本文が「この数値」「この表」「この図」と参照している箇所の画像は必ず開く
4. 画像とテキストの食い違いを確認する。スライドの見出しと貼られたスクリーンショットが
   別物、という齟齬が実際にある

## 出力の読み方

- X の長文 Article は DraftJS 形式。本文中の `atomic` ブロックは画像**または**markdownコードブロックで、
  スクリプトが両方を復元して出現順に並べている
- Instagram のカルーセルは `edge_sidecar_to_children` から全スライドを取る。
  URL の `?img_index=N` は1始まりなので、N枚目は `img_{N-1:02d}.jpg`

## 壊れたときの直し方

このスクリプトは非公式な取得経路に依存しているので、いずれ壊れる。症状別の原因：

- **X で本文が取れない** → `api.fxtwitter.com` の仕様変更かダウン。
  `api.vxtwitter.com` を試す。JSON構造は `tweet.article.content.blocks` と
  `tweet.article.media_entities` を突き合わせている
- **Instagram で `contextJSON` が見つからない** → **まずUAを疑う。**
  Chromeのフル User-Agent を送ると JS描画前提の別ページ（600KB超）が返り、データが消える。
  素朴な `Mozilla/5.0` でないと軽量版（200KB前後、データ入り）が返らない。これが最大の罠
- **どうしても取れない** → 諦めて推測で答えない。
  「取得できなかった、スクリーンショットを貼ってほしい」と正直に言う。
  画像として渡されたものは確実に読める

## 禁止事項

取得に失敗した状態で、URLの中身について推測で答えない。
分からない場合は分からないと言う。これがこのスキルの存在理由そのもの。
